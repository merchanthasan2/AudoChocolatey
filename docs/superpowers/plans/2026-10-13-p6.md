# P6: Background, Control and Safety

> superpowers:executing-plans (Native). Test cases are the contract; interfaces exact. Design: architect, 2026-10-13. Owner approved starting P6 (a, b, c).

**Goal:** Quantum Updater keeps apps current in the background, lets people decide per app, and makes every change safe and reversible.

**Spec:** §4–§6; docs/COMPETITIVE.md.

## Global Constraints
- **New dependencies:**
  - `tauri-plugin-single-instance = "2"` (2.5.x);
  - `tauri-plugin-dialog = "2"` (2.8.x), used from Rust only, so no `dialog:*` capability;
  - direct `windows = "0.62"`, already in Cargo.lock, for WinRT toasts, Task Scheduler COM and the metered-network check.
  - Not used: `tauri-plugin-notification` (falls back to PowerShell's identity) and `tauri-plugin-autostart` (uses the Run key, which Windows skips for admin apps; ADR 014).
- **New `windows-sys` features:** `Win32_System_Power`, `Win32_System_Restore`, `Win32_Security_WinTrust`, `Win32_Security_Cryptography`, `Win32_System_SystemInformation`, `Win32_System_TaskScheduler`.
- **Command pattern:** every command goes into `build.rs` `COMMANDS` and `capabilities/main.json` (`allow-<kebab>`); bindings are regenerated by `cargo test`.
- **Plain language:** toast, tray and new screen text names apps, not tools (ADR 027). A Rust test copies `policy.mjs`'s regex for Rust-side strings.
- **Nothing auto-runs from user-writable files.** Import, rollback and history go through Rust-held, re-validated data, and every change passes `allowed()` / `permitted()`.
- **Autostart:**
  - The Scheduled Task points only at the installed exe under Program Files.
  - It is registered through COM with the XML in memory (no temp file) and is per user.
  - It is refused in debug builds and over-the-shoulder setups, and removed on uninstall.
  - It is **off until the person says yes** to a one-time prompt (owner default 2026-10-13: ask, don't assume).
- **Live checks on the owner's PC need approval first.** Test apps must not already be installed.

## P6a Background
1. **Launch modes and single instance.**
   - `main.rs` gets `LaunchMode { Normal, Background, UnregisterAutostart }` from exact-match arguments only.
   - `--unregister-autostart` exits before any plugin loads.
   - Single-instance is the first plugin. A second launch shows and focuses the window; argv is never acted on beyond `--background`.
   - `SetCurrentProcessExplicitAppUserModelID`.
   - `relaunch_as_admin` passes `--after <pid>`, and the new instance waits up to 15 s for the old one to exit.
   - *Tests:* `parse_args` table (garbage, `--after abc`, duplicates).
2. **Window, close-to-tray, start-in-tray.**
   - The window starts hidden; `setup` shows it unless the mode is Background and start-in-tray is on. Showing never depends on the tray.
   - Pure `close_action(close_to_tray, jobs) -> Hide | Guard | Close`. Tray "Quit" uses the same guard. The one-time "Still running in the tray" note uses `tray_hint_shown`.
   - *Tests:* `close_action` table.
3. **Tray.**
   - Menu: Open, Check now, Pause / Resume, Quit, plus "Update all (n)" routed through `update_all`.
   - Tooltip: "Quantum Updater: 3 updates ready".
   - `TrayAction::from_id`; unknown ids are ignored.
   - *Tests:* `from_id`; no tool names in strings.
4. **Scheduler.**
   - One task wakes every 5 minutes and compares wall-clock time, so sleep is handled; "Check now" and interval changes wake it early.
   - Pure `due(now, launched_at, last_check, interval_h)`: the first check comes 2 minutes after launch.
   - Pure `diff_notify(prev, next)`: keys are `rule_key@version`, and only additions notify.
   - `background.json` (64 KB cap) keeps the last check time and what was notified.
   - `AppState.check_lock` stops two checks at once; a check waits while a job runs (up to 30 minutes).
   - Event `updates://changed`; commands `check_now` and `get_background_status`.
   - *Tests:* `due` table (startup, interval, clock jump, interval change) and `diff_notify` table.
5. **Toasts.**
   - WinRT `CreateToastNotifierWithId("in.quantumstep.quantumupdater")`, XML built with the DOM (never string formatting); names capped at 60 characters.
   - Fixed launch `open:updates`, which opens the Updates view.
   - None when notifications are off, when the app runs as another account, or in debug builds.
   - Pure `toast_lines(change)`, for example "Firefox and 2 more can be updated".
   - *Tests:* `toast_lines` table; no tool names.
6. **Start at login (Scheduled Task).**
   - A `TaskStore` trait, with a COM implementation running on its own MTA thread.
   - Pure `task_xml(exe, sid)`:
     - logon trigger for that user, delayed 15 s;
     - interactive token, highest privileges;
     - no battery stop, no time limit, ignore-new, priority 4;
     - the path XML-escaped.
   - Task name `\QuantumStep\Quantum Updater <SID>`.
   - Pure `allowed(exe, program_files, elevated, same_user, debug)`.
   - Pure `reconcile(want, existing, exe)`, run at every start.
   - The Settings change applies the side effect before saving; on failure the setting stays off and the reason is shown.
   - The first-run card "Keep apps updated in the background?" uses `background_prompted`.
   - NSIS `hooks.nsh` `NSIS_HOOK_PREUNINSTALL` runs `--unregister-autostart`, except in update mode.
   - *Tests:* `task_xml` golden (path with `&`), `allowed` table, `reconcile` table, side-effect order with `FakeTaskStore`.
   - *Live (approval):* turn on, check the task, sign out and in, toast click, second launch, uninstall removes the task.

## P6b Control
1. **Per-app policy in `rules.rs`.**
   - `RuleKind = Never | SkipVersion{version, after} | Auto | Ask`. Skip expiry falls back to `after`.
   - Rules schema version 2, so older builds open the file read-only.
   - Pure `effective(mode, rule)`.
   - Row menu: Automatic / Ask first / Never, plus Skip this version.
   - *Tests:* expiry to `after`, `effective`, v1 files load.
2. **Automatic mode and conditions.**
   - Settings `auto_update {Notify, Automatic}`, `auto_rules {skipOnBattery, skipOnMetered, quietHours}`, `restore_point`, `tray_hint_shown`, `background_prompted`.
   - Probes: power status, connection cost, local time. Unknown means hold.
   - Pure `may_auto_install(settings, probe) -> Result<(), Hold>`, with the hold reason shown in Settings.
   - Auto-install covers only shown updates whose policy is Auto, through `permitted()` and the admin check. It never installs new apps and never touches unknown-version rows.
   - *Tests:* quiet hours across midnight; battery, metered and unknown; ruled and other-account items never auto-queued.
3. **Export and import.**
   - Format `{"format":"quantum-updater-apps","schemaVersion":1,"exportedAt","apps":[{key?,source,id,name}]}`, with no versions.
   - Rust-side dialogs only; paths never cross IPC.
   - `export_apps`; `import_pick` (1 MB cap, 500 apps) returns a preview with a token and per-row status.
   - `import_apply(token, indices)` uses only Rust-held, validated install operations.
   - Non-catalog rows show their package id and start unticked.
   - *Tests:* parse and validate (wrong format, newer schema, oversized, 501 entries, injection ids, duplicates, pinned versions ignored), apply only takes stored indices, stale token.
4. **Remove several apps.**
   - Installed page checkboxes plus a confirm dialog listing names, at most 50 apps.
   - `refuse_protected_uninstall` blocks Quantum Updater itself, WebView2 Runtime, App Installer (winget) and Chocolatey.
   - *Tests:* protected table; batch refused.
5. **Settings page and admin banner.**
   - Sections: Background, Automatic updates, Safety, Your apps (export and import), App updates (placeholder until signed releases).
   - `Overview.sameUser`.
   - `logic/adminBanner.ts` `bannerFor(overview)` (needs admin / other account), rendered by one `AdminBanner.svelte`.

## P6c Safety
1. **Restore point before a batch.**
   - `RestorePoint` trait; `SRSetRestorePointW` BEGIN/END (`APPLICATION_INSTALL`) in `spawn_blocking` with a 3-minute timeout.
   - Made once each time the queue goes from idle to busy, when the setting is on.
   - Never blocks the queue. The outcome note ("requested", "System Restore is off", "couldn't create one") appears in the activity panel.
   - *Tests:* fake error and timeout, and the jobs still run.
2. **History.**
   - `Job.dismissed`; "Clear finished" hides jobs in the panel but keeps their history.
   - New History page and `get_history()`.
   - *Tests:* clear keeps history; dismissed survives a restart.
3. **Rollback.**
   - `OpKind::Rollback`, created only by `rollback(job_id)`; `enqueue` refuses it from JS.
   - Offered only when all of these hold:
     - the job is a succeeded update;
     - `from_version` is known;
     - the source is winget or Chocolatey;
     - the installed version equals `to_version`;
     - the source still lists `from_version` (winget `show --versions`, Chocolatey feed).
   - Commands: winget `install --version V --exact` (no `--force`); Chocolatey `install --version V --allow-downgrade`.
   - Verified against V; then a "skip that version" rule is added automatically.
   - Might end up Chocolatey-only if winget won't downgrade (live check).
   - *Tests:* offer table, command shapes, JS-sent rollback refused, auto-skip rule.
4. **Signer note.**
   - When a job reaches Installing, the downloaded installer (winget temp folder, Chocolatey temp folder) is checked with `WinVerifyTrust` (cache-only revocation).
   - The result is shown as "Installer signed by Mozilla Corporation". It is never a gate and never says "verified safe".
   - *Tests:* pure `pick_installer(dir, since)`; signed vs unsigned file.
5. **Security first.**
   - `CatalogApp.security` for browsers, Zoom, 7-Zip, WinRAR, Java, PDF readers, VLC, Notepad++, PuTTY, WinSCP, Git, Node.js, Python, password managers, VPNs and Thunderbird.
   - Those updates sort first, labelled "Important to keep current". No CVE claims.
   - *Tests:* sort order; flag across sources.

## Review Focus
1. Autostart from a user-writable path, a task left behind after uninstall, or an invisible app (window hidden while the tray failed at logon).
2. `relaunch_as_admin` with single-instance leaving no app running; toasts to the wrong account.
3. Auto-install acting while a probe can't be read; ruled or other-account items auto-queued.
4. A forged import or forged history leading to an install or rollback of something else.
5. A restore point blocking the queue; "verified" wording; batch uninstall removing WebView2, winget or the app itself.

## Deferred
Idle and fullscreen detection, opening a view from a toast after the app exited, a tray badge, the Chocolatey bootstrap, signer checks for installers embedded in a Chocolatey package (all P8 or later).
