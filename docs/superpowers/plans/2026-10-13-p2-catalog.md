# P2: Combined Catalog, Proper Names and a Real Marketplace

> superpowers:executing-plans (Native). Test cases are the contract; interfaces exact.

**Goal:**
- One entry per app across winget and Chocolatey.
- Human names everywhere: no raw `vcredist140`, no "CrystalDiskInfo 9.9.2".
- A Marketplace home driven by the curated catalog: featured apps, 10 categories, 5 bundles.
- An app details panel.
- Updates owned by the right source.

**Architecture:**
- `src-tauri/catalog/apps.json` (96 apps, validated live by `scripts/validate-catalog.mjs`) is embedded with `include_str!` and parsed once at startup.
- `catalog/` module: model plus loader, `normalize`, `merge` (search results become `AppEntry`), `names` (display names for installed and update rows), and `owner` (de-duplicating updates).
- Chocolatey titles for unmapped choco rows come from the community feed (cached per session).
- New commands: `marketplace_home`, `marketplace_category`, `get_app`, `install_bundle`. `search` returns merged `AppEntry` results.

**Spec:** §4.2, §5.4.

## Global Constraints
- **Merge only when certain:**
  - a catalog mapping; or
  - the normalized names are equal **and** the winget publisher token appears in the choco id or title.
  
  Otherwise keep the entries separate. Different version numbers in the names never merge ("Python 3.11" ≠ "Python 3.12").
- **Best source:** winget if the app has it, otherwise Chocolatey.
- **Update ownership:** when both sources report an update for one catalog app, Chocolatey owns it (choco only lists what choco installed) and the winget row is dropped.
- Names never get longer than the source name. Display names never change which package is installed.

## Review Focus
1. **Near-miss names must not merge:**
   - `Python 3.11` vs `Python 3.12`;
   - `Visual Studio Code` vs `Visual Studio Code Insiders`;
   - `Firefox` vs `Firefox Developer Edition`;
   - a winget `Notepad++` vs an unrelated choco `notepad2`.
   
   Pinned in T2.
2. **A Chocolatey title lookup that fails or is offline** leaves the id as the name, with no error. Pinned in T3.
3. **A bundle where some apps are already installed** queues only the missing ones; queueing a bundle twice queues nothing new. Pinned in T4.
4. **A winget display name with a version that isn't the installed one** ("Python 3.13.15 (64-bit)" for version 3.13.15150.1013) is not mangled. Pinned in T3.
5. **The catalog itself:**
   - unique keys;
   - bundle references that exist;
   - every category known;
   - ids that pass the newtypes.
   
   Pinned in T1.

### T1: Catalog model and loader
`catalog/mod.rs`:
- `Catalog { categories, apps, bundles }`, with `Catalog::embedded()` (a panic in tests only) plus index maps by winget id and choco id (lowercase).
- `AppEntry { key, name, publisher?, blurb?, category?, winget?, choco?, version?, homepage?, best: SourceKind, curated: bool, iconKey }` (ts-rs).

Tests:
- The embedded catalog parses.
- Keys are unique.
- Bundle apps exist.
- Categories are known.
- Every winget/choco id passes `WingetId`/`ChocoId`.
- Every app has at least one source.
- `by_winget("mozilla.firefox")` gives `firefox`.

### T2: Normalize and merge search results
- `normalize(name)`: lowercase; drop `(...)` groups, ™ and ®, and the tokens `x64 x86 64-bit 32-bit desktop`; `+` becomes `plus`; alphanumerics only.
- `merge(winget: Vec<SourcePackage>, choco: Vec<SourcePackage>, cat) -> Vec<AppEntry>`: catalog first, then the heuristic, else separate. winget order first, then choco-only entries.

Tests:
- Catalog mapping merges both sources into one `firefox` entry with `best=winget`.
- The heuristic merges an unmapped pair (`Contoso.Widget` "Contoso Widget" + choco `contoso-widget` "Contoso Widget").
- The near misses listed above stay separate.
- A choco-only result gets `best=choco` and its description.
- Merged entries keep the catalog name and blurb.

### T3: Display names and update ownership
- `strip_version_tail(name, version)`: "CrystalDiskInfo 9.9.2" with version 9.9.2 gives "CrystalDiskInfo". A name whose tail isn't the exact version stays as it is.
- `display_name(source, id, raw_name, version, cat, titles)`: the catalog name wins, then the choco feed title, then the stripped name.
- `owner_dedupe(candidates, cat)`.
- `ChocoTitles` (an in-memory cache, 4 concurrent requests, failure leaves None).

Tests:
- Every case listed above.
- A winget and a choco candidate for `vscode` keep only the choco one.
- An unmapped duplicate keeps both.

### T4: Commands
- `marketplace_home() -> Home { featured: AppEntry[], categories: { id, name, count }[], bundles: Bundle[] }`
- `marketplace_category(id) -> AppEntry[]`
- `search` returns `Listing<AppEntry>`
- `get_app(key) -> AppDetails { entry, description?, homepage?, publisher?, license?, version? }` (winget show / choco feed)
- `install_bundle(id) -> string[]`, which skips installed apps using the cached installed list.
- `list_installed` and `list_updates` apply the display names, and updates also get the owner dedupe.

Tests: the bundle skip logic (`bundle_ops(bundle, installed_ids, cat)`).
