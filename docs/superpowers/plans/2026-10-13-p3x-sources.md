# P3 extras + sources: reliable queue, rules, clear failures, Store, Scoop, backup sources

> superpowers:executing-plans (Native). Test cases are the contract; interfaces exact. Design: architect, 2026-10-13.

**Goal:**
- The queue survives restarts, can pause, and checks that each install or update really took effect.
- People can skip a version or never update an app, with a Hidden list to undo it.
- Failures say why in plain words. Source names ("winget", "Chocolatey") leave the normal UI.
- More apps: Microsoft Store, live category extras, and Scoop.
- When one source fails, the app tries a backup source.

**Spec:** §4–§6. Changes of decision (owner, 2026-10-13): Microsoft Store and Scoop are now in scope (the spec listed them as non-goals); source names are hidden; backup sources apply to installs and updates.

## Global Constraints
- The app is always elevated (ADR 008). The webview is untrusted: every id from JS goes through a validated newtype; tags, alternates and fallbacks are looked up in Rust, never taken from JS.
- Nothing runs from a file on disk without a click. `jobs.json` and `rules.json` are user-writable: they are revalidated, size-capped, and never auto-executed.
- Plain copy: no "winget", "Chocolatey", "choco", "Scoop" or "Store" source names in normal UI or failure messages. The details panel's "Advanced" block and Settings → Advanced are the only exceptions (enforced by `check-frontend-policy.mjs`).
- winget failures are classified by exit code only (its text is localized); Chocolatey and Scoop text is English-only and may be pattern-matched.
- Every new command: `build.rs` `COMMANDS` + `capabilities/main.json` `allow-<kebab>`; bindings regenerated by `cargo test`.
- Live tests on the owner's PC need approval, and must first confirm the test app is not already installed.

## Review Focus
1. Closing the app while an installer runs: Job Object kill-on-close kills the installer. Add a close guard ("An install is running. Close anyway?") in T2.
2. Verification false alarms: browsers and self-updaters, `1.2` vs `1.2.0.0`, "Unknown" versions. T3 normalizes through `versions.rs`; Unknown is silent.
3. Chocolatey exit codes passed through from packages, and text patterns seen on one PC only. T1 fixtures come from real runs where possible.
4. Store apps from an over-the-shoulder admin token land in the wrong profile; MSIX rows that never correlate. T6 refuses when the shell user differs from the token user.
5. Rule keys across owner changes and fallback: catalog-key equivalence, a skip that "expires" when a source lowers its version, ruled apps returning through a stale list after a failed refresh. Pinned in T4.

### T1: Failure reasons, needs-admin guard, neutral messages
- `src/fsutil.rs`: `write_atomic(path, &[u8])`, `load_versioned<T>(path, max_bytes)`; moved out of `settings/mod.rs` (settings, jobs and rules share them).
- `jobs/failure.rs` (ts-rs): `enum FailureReason { NotElevated, InstallerBusy, RebootPending, HashMismatch, DownloadFailed, Offline, NotFound, NoApplicableInstaller, ProhibitsElevation, AppRunning, DiskFull, Blocked, Interrupted, TimedOut, InstallerError, AlreadyCurrent, Unknown }`, `fn message(&self, name: &str) -> String`.
- `exit_codes::classify(source, kind, code, log_tail: &[String]) -> Outcome`:
  - winget by code: 0x8A150011 HashMismatch; 0x8A150008 / 0x8A15002E / 0x8A150086 DownloadFailed; 0x8A150107 Offline; 0x8A150014 NotFound; 0x8A150010 NoApplicableInstaller; 0x8A150056 / 0x8A15007D ProhibitsElevation; 0x8A15010A RebootPending; 0x8A150102 InstallerBusy; 0x8A15002B AlreadyCurrent (measured live, ends as Skipped).
  - MSI codes, both sources: 1618 InstallerBusy, 1603 InstallerError, 1625 Blocked; Chocolatey 350 / 1604 RebootPending.
  - Chocolatey text: "checksum" mismatch → HashMismatch; "not found with the source(s)" → NotFound; "remote name could not be resolved" / "Unable to connect" → Offline; "(404) Not Found" → DownloadFailed; "not running from an elevated" → NotElevated; "pending system reboot" → RebootPending.
- `Job` gains `reason: Option<FailureReason>`; `error` = `reason.message(name)`; the raw code goes to the log only.
- `AppState.elevated` (read once). `commands::jobs::refuse_unelevated(elevated)` → `AppError{code:"needs_admin"}` in `enqueue`, `update_all`, `retry_job`. `WorkerDeps.elevated`: a non-elevated worker fails jobs with NotElevated before spawning.
- Neutral wording for `worker.rs` "{tool} is not installed" and `SourceError` messages.

Tests: classify table (every code and pattern above, fixtures `tests/fixtures/choco/fail-*.txt`); every `message()` free of source names (case-insensitive); `refuse_unelevated(false)` errors; a non-elevated worker never calls `FakeStream.run`.

### T2: Persisted queue, recovery, pause, close guard
- `jobs/persist.rs`: `jobs.json` in `data_dir` = `{schemaVersion, jobs}`; at most 200 finished jobs plus active ones (memory and disk); logs are not persisted. Writer task fed by a `tokio::sync::watch` snapshot; sent on enqueue, phase change, clear, pause; never on progress.
- `recover(jobs) -> Vec<Job>` (pure): Preparing/Waiting/Downloading → Cancelled "Stopped when the app closed"; Installing/Verifying → Failed(Interrupted); Queued → Cancelled "Not started". Never auto-requeue; the drawer offers "Retry N not started".
- Corrupt or > 2 MB file: back up to `jobs.json.bad`, start empty. `Inner.next` = max persisted `jN` + 1.
- Pause: `Inner.paused`; the worker starts nothing new while paused; the running job finishes. `get_queue` and `queue://changed` return `QueueSnapshot { jobs, paused }`. Not persisted. Commands `pause_queue`, `resume_queue`.
- Close guard: closing the window while a job is Installing asks first (Tauri `CloseRequested` → UI dialog).

Tests: recover table; id continuity; 200 cap; corrupt-file backup; round-trip of a finished job; "paused queue never starts the next job but the current one finishes" (FakeStream).

### T3: Post-success verification
- `WorkerDeps.verifier: Option<Arc<dyn Verifier>>`, `async fn installed_version(&SourceRef) -> AppResult<Option<String>>`: winget `list --id X --exact --source <src>`; Chocolatey `list <id> --exact -r` (v1 adds `--local-only`); Scoop per T9. 30 s timeout.
- "Before" read during Preparing; "after" during Verifying. `verdict(kind, before, after) -> Verify { Confirmed, Unchanged, Unknown }` (pure, via `versions::compare`).
- `Job` gains `verify`, `fromVersion`, `toVersion`. The phase stays Succeeded: never a failure, never a fallback trigger.
- UI on Unchanged: an amber note and the toast "{name} finished, but still reports {v}. It may finish updating after you restart it."

Tests: verdict table (including `1.2` vs `1.2.0.0`, Unknown); fake verifier gives Verifying → Succeeded; verifier error still Succeeded; fixtures `winget/list-id.en.txt`, `list-id-missing.en.txt`.

### T4: Rules and the Hidden list
- `rules.json` in `config_dir` (`fsutil`, max 500 rules, newer schema = read-only).
- `Rule { key, target: SourceRef, name, kind: RuleKind, createdAt }`, `RuleKind = Never | SkipVersion { version: PkgVersion }` (serde tag `kind`).
- `rule_key(&SourceRef, &Catalog)`: `app:<catalog key>` for catalog apps, else `<source>:<id lowercase>`.
- `apply_rules(raw, &mut rules) -> (visible, hidden)` (pure): SkipVersion hides while `available == version`, and is deleted once `available` is greater.
- `AppState.last_updates` keeps the raw list; `collect_updates` applies rules, so `update_all` and the future scheduler skip ruled apps. A failed refresh keeps rules applied to the last good list.
- `list_updates` → `UpdatesListing { items, hidden: HiddenUpdate[], rules, sourceErrors }`. Commands `set_rule(target, name, kind)`, `remove_rule(key)` recompute from `last_updates` (no new check). Event `rules://changed`.
- UI: per-row "⋯" menu (Skip this version / Never update); a collapsible "Hidden (n)" section with Restore.

Tests: expiry (equal, greater, lesser, not comparable); catalog-key equivalence across winget/Chocolatey; `update_all` excludes ruled apps; persistence round-trip; a 501st rule is refused.

### T6: Microsoft Store
- `SourceKind::Msstore`; `StoreId` regex `^(9[A-Z0-9]{11}|XP[A-Z0-9]{12})$` (uppercase); `SourceRef::new` dispatches.
- argv: `install|upgrade --id X --exact --source msstore --silent --disable-interactivity --accept-package-agreements --accept-source-agreements` (same trusted winget exe). No sizer; indeterminate ring. Live-verified 2026-10-13: install exit 0 for the real user; already installed → 0x8A15002B; uninstall 0.
- `WingetSource::search_store` (`--count 20`) runs in parallel inside `search`. `show(source, id)` takes the source. `list_installed` / `list_upgrades` map `msstore` rows with a valid `StoreId`.
- Merge: Store entries are never heuristic-merged; only an `msstore` field in `catalog/apps.json` (checked by `validate-catalog.mjs`) links them. Install priority: winget, Chocolatey, Store, Scoop.
- `AppEntry.msstore`; icons `msstore:<id>` (installed MSIX logo, else publisher URL from `show`); update `icons::parse_request`.
- Setting `store.enabled` (default on); `refuse_disabled_store`.
- AppDetail notes: "Installing means you accept the publisher's licence and the Microsoft Store terms."
- `system::shell_user_matches()` (token SID vs. the shell window's process token SID); Store jobs are refused when false.

Tests: StoreId accept/reject (`9n…` lowercase, `-x…`, 13 chars); argv; fixtures `winget/search-msstore.en.txt`, `search-tag-msstore.en.txt`; merge keeps Store "Brave Browser" apart from `Brave.Brave`.

### T7: Backup sources (installs and updates)
- `Catalog::alternates(&SourceRef) -> Vec<SourceRef>`: from catalog mappings only (never from JS, never from heuristic merges). Order: winget, Chocolatey, Store, Scoop.
- One job, at most one fallback: `Job` gains `attempt: u8`, `via: Option<SourceRef>`; `Job::restart_attempt()` returns to Preparing and clears progress; the log gets a separator line. `op` stays the user's request, so `jobFor` and dedupe still work.
- `fallback_target(job, reason, cat, enabled) -> Option<SourceRef>` (pure):
  - Never if the job reached Installing, or for Cancelled, InstallerBusy, RebootPending, NotElevated, Offline, AppRunning, DiskFull, LowMemory, Blocked, Interrupted, TimedOut, InstallerError, Stopped, Skipped, or a disabled or missing alternate.
  - **Install:** reasons NotFound, DownloadFailed, HashMismatch, NoApplicableInstaller, ProhibitsElevation → first enabled alternate.
  - **Upgrade:** reasons HashMismatch, DownloadFailed, NotFound, NoApplicableInstaller; only winget-owned → Chocolatey (`choco install <id> -y`, which upgrades in place and adopts the app); only if the Chocolatey feed's latest version is greater than the installed one; never Chocolatey → winget; never to or from Store/Scoop; never for Chocolatey ids ending `.portable` / `.commandline`, winget installer types msix/portable, or catalog apps flagged `noUpgradeFallback`.
  - Uninstall: never.
- Verification (T3) checks `via`. Rules follow the catalog key. Afterwards `owner_dedupe` keeps the Chocolatey row.
- UI: "Trying another way to install/update {name}…"; Advanced shows what was actually used ("Updated with Chocolatey after the usual source couldn't download it. Future updates come from Chocolatey.").

Tests: eligibility table (each rule above, both directions); no fallback after Installing; second attempt success verified against `via`; batch count unchanged by a fallback; `owner_dedupe` after adoption keeps only the Chocolatey row.

### T9: Scoop (only when already installed) — DROPPED (owner, 2026-10-13; ADR 026). Replaced by an "Allow admin access" (UAC) banner.
Design: architect addendum 2026-10-13. Scoop isn't installed on the owner's PC: T9a's live checks and all fixtures need it installed (owner approval required).
- **T9a `sources/userproc.rs`:** run as the signed-in user without admin rights. `ShellToken::acquire()` per run: shell window → process (must be `<WindowsDir>\explorer.exe`) → token; pure `check_token(TokenFacts)` requires same user SID (else over-the-shoulder: refuse), not elevated, Medium integrity, same session; `DuplicateTokenEx`. `UserStreamRunner`/`UserRunner` implement the existing traits: `CreateEnvironmentBlock`, profile dir as cwd, `CreateProcessWithTokenW(LOGON_WITH_PROFILE, CREATE_SUSPENDED|CREATE_UNICODE_ENVIRONMENT|CREATE_NEW_CONSOLE)`, hidden window, inheritable pipe ends closed after launch, Job Object assigned before `ResumeThread`, end on process exit then drain pipes for ≤ 2 s, caps 1 MB total / 4 KB per line. No shell window → source state "Waiting for you to sign in".
- **What runs:** always `<System32>\WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive -ExecutionPolicy RemoteSigned -Command <constant script>`; the script sets UTF-8 output and runs `& $env:QU_SCOOP $env:QU_VERB $env:QU_ID`. Package data travels only in `QU_*` environment variables; the verb comes from a Rust enum; never `--global`. `QU_SCOOP` = `<root>\apps\scoop\current\bin\scoop.ps1` (root from `HKU\<sid>\Environment\SCOOP` if literal absolute, else `<profile>\scoop`). Nothing from the Scoop folder is ever run by the elevated process.
- **T9b `sources/scoop/{mod,args,parse}.rs`:** JSON via PowerShell (`list`, `status`, `search`, selecting only the needed properties); `scoop update` at most once per 24 h; only buckets already added. `ScoopId` = `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}/[A-Za-z0-9][A-Za-z0-9._+-]{0,99}$`. Phases from "Downloading", "Checking hash", "Extracting", "Linking", "was installed successfully"; classifier: "Couldn't find manifest" NotFound, "Hash check failed" HashMismatch, "is already installed" Skipped, "still running" AppRunning, "remote server returned an error" DownloadFailed. Verification is mandatory (exit codes unreliable).
- **T9c wiring:** `SourceKind::Scoop`, setting `scoop.enabled`, catalog `scoop` field (validator checks the manifest over HTTPS), never merged by name, install priority last, install-only fallback, owns its updates, icons from homepage only. Never install Scoop itself; Settings → Advanced says "Not found. See scoop.sh".

Tests: `check_token` table; env block (no package data on the command line); output caps and drain-after-exit; `#[ignore]` live test (Medium integrity, no console flash, `TerminateJobObject` kills a `ping -t` tree); `ScoopId` accept/reject; JSON fixtures (list, status, search, empty, single object); log fixtures (install ok, not found, hash fail, already installed); merge never joins Scoop by name.
