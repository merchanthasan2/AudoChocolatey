# P6d Lists: implementation plan

> Design: architect, 2026-10-17, from the brief in [p6](2026-10-13-p6.md) § P6d. **Awaiting owner approval** of the decisions marked ★.
> Test cases are the contract. Every new command goes into `build.rs` and `capabilities/main.json`.

## 0. Findings that shape the design
- `winget list` rows with no source already parse (`row_source` returns `None`). Their ids encode the registry location: `ARP\<Machine|User>\<X64|X86>\<key>` or `MSIX\<PackageFullName>`. The component rules below hide about 95 rows of the owner's fixture (`tests/fixtures/winget/list.en.txt`, 245 rows), because winget repeats rows. None of the near-misses are hidden.
- ★ **No honest download size.** Chocolatey `PackageSize` is the size of the package file (25 KB for Firefox), and winget `show` has no size field. So the Size column is deferred.
- **Nothing opens URLs today.** `ShellExecute` on a URL from the admin process can start the browser as admin, so "What's new" needs an unelevated opener (ADR 030).
- ★ **Reinstall needs `--force`.** This relaxes the P1 "never `--force`" invariant to "`--force` if and only if mode is Reinstall".
- **`OpRequest.version` is accepted from JS today** (always `null` in practice). P6d closes this, in line with P6c's "rollback refused from JS".
- **HKCU `ARP\User\…` entries can be written by the standard user**, so they never drive a link.
- **The policy check scans only `.svelte` files.** `logic/sources.ts` already holds the tool-name map and isn't scanned.

## 3. List architecture
**Decision:** pure TS logic, one presentational `AppList` frame, and the pages keep their own rows, actions and job wiring. A god-component `AppTable` is avoided.

| Piece | File | Responsibility |
|---|---|---|
| Query logic | `app/src/lib/logic/listView.ts` | filter, search, sort, counts |
| Version order | `logic/versions.ts` | port of `versions.rs::compare`, sharing its test table |
| Selection | `logic/selection.ts` | prune, header state, shift-range |
| Toolbar fit | `logic/toolbarFit.ts` | how many actions fit |
| Primary label | `logic/primaryAction.ts` | "Update 3 selected" / "Update all" / "Update 4 shown" |
| Prefs | `stores/app.svelte.ts` `ListState` | text, label filter, pref mirrored from Settings (400 ms debounce) |
| Frame | `components/AppList.svelte` (generic `T`) | controls row, header, rows or tiles, skeleton/empty/error states |
| Toolbar | `components/ListToolbar.svelte` | actions plus overflow (ResizeObserver and `fitActions`) |
| Menu | `components/MenuButton.svelte` | portal menu, Esc, outside-click, arrow keys; `RowMenu` becomes a wrapper |
| Chips | `components/SourceChips.svelte` | single-select radiogroup with counts; empty chips hidden unless selected |
| Header | `components/ListHeader.svelte` | sort buttons with `aria-sort` |
| Row | `AppRow.svelte` + `density: 'list'\|'compact'` + `cells?` | compact rows 44 px; the running bar is a 3 px bottom edge |
| Tile | `components/AppTile.svelte` | grid card `auto-fill minmax(220px,1fr)`; exits with opacity and scale 0.96 |

```ts
export interface ListItem { key: string; name: string; id: string; label: SourceLabel; component: boolean;
  version: string; newVersion?: string; released?: string | null; security?: boolean }
export interface ListQuery { text: string; label: SourceLabel | 'all'; hideComponents: boolean; sort: ListSort; dir: SortDir }
export function matchesText(i: ListItem, text: string): boolean
export function labelCounts(items: ListItem[], q: Pick<ListQuery,'text'|'hideComponents'>): Record<SourceLabel|'all', number>
export function applyQuery<T>(items: T[], view: (t: T) => ListItem, q: ListQuery): T[]
export function compareItems(a: ListItem, b: ListItem, sort: ListSort, dir: SortDir): number
export function compareVersions(a: string, b: string): number
export function keepSelected(selected: Iterable<string>, selectableVisible: ReadonlySet<string>): string[]
export function headerState(sel: number, selectable: number): { checked: boolean; indeterminate: boolean; disabled: boolean }
export function rangeKeys(order: string[], anchor: string, target: string): string[]
export function fitActions(widths: number[], available: number, overflowW: number, gap: number): number
export function primaryAction(selected: number, shownIdle: number, filtered: boolean): { label: string; scope: 'selected'|'all'|'shown' } | null
```
- **Selection:**
  - Pruned to visible, selectable rows, so we never act on rows the person can't see.
  - Busy rows aren't selectable. On Installed, only managed rows that aren't linked are selectable.
  - Shift-click selects a range; `clickGuard(800)` stays on the primary button.
- **Sorting** is remembered in Rust settings (typed and validated; survives WebView profile resets):
  - "Suggested" puts security apps first (P6c-5), then sorts by name.
  - Unknown versions and missing dates sort last whichever way.
  - Source sorts by `LABEL_ORDER`, then name.
- **Columns** (container queries hide Released below 760 px and Source below 640 px):
  - Updates: App, Installed, New version (+ What's new), Source, Released, action.
  - Installed: App, Version, Source, note, action.
  - Grid uses a "Sort" menu instead of a header.
- **States:**

  | State | Shows |
  |---|---|
  | Not loaded | Skeleton matching the view |
  | Error with no items | Banner plus "Couldn't read your apps" with Try again |
  | Nothing to show | "You're all set" (Updates) / "No apps found" (Installed) |
  | Filtered to nothing | "No apps match" with "Clear filters" |
  | Source errors | Banners above the toolbar |

- **Kept:** JobButton, per-row bar, `out:collapse`, `visibleUpdates`, `uniqueKeys`, the Hidden section, the batch bar, CountRoll.

| Installed | Remove selected (confirm, at most 50; `refuse_protected_uninstall`) | `enqueue` uninstall; needs P6b-4 |
| | Check again / Add to bundle / Export | as above |

```rust
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq, Serialize, Deserialize, TS)]
#[serde(rename_all = "lowercase")] #[ts(export)]
pub enum OpMode { #[default] Normal, Interactive, Reinstall }
pub struct OpRequest { pub kind: OpKind, pub target: SourceRef, pub version: Option<PkgVersion>,
                       #[serde(default)] pub mode: OpMode }   // old jobs.json loads as Normal
pub fn mode_allowed(kind: OpKind, mode: OpMode, source: SourceKind) -> bool
pub fn refuse_js_only(ops: &[(OpRequest, String)]) -> Result<(), AppError> // version must be None
```
**Allowed modes:**

| kind \ mode | Normal | Interactive | Reinstall |
|---|---|---|---|
| Install | all | winget, Chocolatey | refused |
| Upgrade | all | winget, Chocolatey | winget, Chocolatey |
| Uninstall | all | refused | refused |

**Command shapes:**
- Interactive: winget `--interactive` replaces `--silent`; Chocolatey adds `--not-silent`.
- Reinstall: winget `install --id X --exact --source winget --force --silent …`; Chocolatey `upgrade X -y --force --no-color`.

**Gates:**
- `enqueue` runs `refuse_js_only`, then `allowed()` (now including `mode_allowed`, so retries are re-checked).
- `build_op` rejects disallowed combinations too.
- No fallback and no download timeout when the mode isn't Normal; the 24 h safety limit still applies.
- `update_all`, the tray and auto-install only ever build Normal.
- The P1 test becomes "`--force` if and only if Reinstall"; `--all` is never emitted.

## 5. What's new and release date
| Field | winget `show` | Chocolatey OData (latest) | Store |
|---|---|---|---|
| Notes link | `Release Notes Url:` | `ReleaseNotes`, only if the whole value is one SafeUrl | none |
| Released | `Release Date:` (validated `YYYY-MM-DD`) | `Published` (date part) | none |
| Version guard | `Version` must equal `available_version` | same | |

- **Fetching:** batched after `collect_updates`, outside `check_lock`, 2 at a time, at most 40 items. Cached in memory in `AppState.meta` (6 h hits, 1 h misses, at most 300 entries), then the `updates://info` event. Non-English winget leaves the fields blank.
- **The URL never crosses IPC.** The UI gets `notesHost` and calls `open_release_notes(target, version)`; Rust re-validates its own cached URL.
- **SafeUrl** (`safe_url.rs`): https, domain host (no IP, no localhost, no single label), default port, no userinfo or control characters, at most 2048 characters. Also applied to `parse_show`'s homepage and installer URLs.
- **`shell_open::open_unelevated`** goes through the desktop shell (`IShellWindows` → `FindWindowSW(SWC_DESKTOP)` → `IShellBrowser` → `IShellView::GetItemObject` → `IShellFolderViewDual` → `IShellDispatch2::ShellExecute`) on its own STA thread. On failure it shows a "Couldn't open the link" toast and **never** falls back to an elevated `ShellExecute` (ADR 030).

## 7. Linking "Installed directly" apps
**Catalog schema** (`CatalogApp.local_match`):
```json
"localMatch": { "via": "choco", "publisher": "Tim Kosse", "arch": ["x86"],
                "keys": ["FileZilla Client"], "namePattern": "^FileZilla \\d+(\\.\\d+){1,3}$", "sameMajor": false }
```
- `via` must name one of the app's own ids (never the Store).
- `publisher` and `arch` are required, plus `keys` and/or an anchored `namePattern`.
- The validator checks that no key is shared, that no pattern matches another catalog app's name, and that every `arch` value is valid.

**Modules:**
```rust
// sources/arp.rs (moved from icons/win.rs, which then reuses it)
pub fn parse_arp_id(id: &str) -> Option<ArpId<'_>>
pub fn read_entry(id: &ArpId) -> Option<ArpEntry>   // HKLM, WOW64 view chosen by arch
// catalog/local_match.rs (pure)
pub struct LocalLink { pub app_key: String, pub target: SourceRef }
pub fn link_all(entries: &[(String, ArpEntry)], managed_app_keys: &HashSet<String>, cat: &Catalog) -> HashMap<String, LocalLink>
```
**Matcher, all steps required:**
1. **Machine scope only** (HKCU can be written without admin).
2. Publisher present and equal (ignoring case).
3. The entry's arch is in `rule.arch`.
4. The entry's key is in `keys`, or `namePattern` matches the DisplayName.

**Ambiguity rules:**
- Two or more candidate apps for one entry: no link.
- Two or more local entries for one app: none link.
- A managed twin on this PC: no link.
- The target's source turned off: no link.

★ **How a linked app is updated:**
- **Installed:** the row says "Can be kept up to date here" and is not selectable for Remove.
- **Updates:** a separate **"Also updatable here"** section below the list.
  - Each row has its own Update button and a one-time confirm: "Quantum Updater will run FileZilla's installer over the copy you have."
  - The button enqueues an `install` of `link.target`, which is already JS-permitted.
  - Linked rows are **never** in `items`, so "Update all", the tray, auto-install and toasts never touch them.
  - A row appears only when the installed version has a digit and the latest is newer (`sameMajor` respected). Skip and never rules apply.

*Tests:*
- each rule kind (key only, pattern only, both); publisher mismatch;
- `ARP\User\…` refused; arch mismatch;
- near-misses "FileZilla Server 1.8.2" and "FileZilla Pro 3.69";
- two apps for one entry; two entries for one app; a managed twin; Chocolatey off;
- installed version "Unknown" gives no update; `sameMajor` blocks 24 → 26;
- a linked row is never in `upgrades_to_ops(items)`.

★ **First entries are WinSCP and FileZilla, verified live on a clean VM, not the owner's PC** (the owner has both installed). Node.js is deferred: its MSI product code changes every release, and LTS versus Current is ambiguous.

## Deferred
- **Download size:** possibly from an https HEAD `Content-Length` of the winget installer URL, alongside P6c-6, with its own security note.

## Main risks
1. **A wrong link installs a different program as admin.** Mitigations: HKLM entries only, arch and publisher guards, exactly one candidate both ways, never in batches or auto-install, a per-app confirm, and VM verification.
2. **An elevated browser.** Mitigation: never `ShellExecute` URLs from the admin process; use only the shell-dispatch path, with no fallback.
3. **The `--force` relaxation and Interactive mode.** Mitigations: Rust's mode table is the only authority, the JS version-pin gap is closed, and there's no fallback or download timeout for non-Normal jobs.
4. **Components hiding a real app.** Mitigations: catalog apps are exempt; it applies to Installed only; the rules are anchored and reviewed; the hidden count is always visible.
5. **CSV formula injection** (handled), and Excel locales that use `;` as the separator (a known limitation).
6. **Metadata fetch load:** about 40 `winget show` calls per check, 2 at a time, cached.
