# Drivers: signed driver updates, maker tools and a driver list

> superpowers:executing-plans (Native). Test cases are the contract; interfaces exact. Design: architect, 2026-10-13.
> **Status: approved by the owner on 2026-10-13.** Slot: after Payment and licensing, before P8. Live checks still need approval each time.

**Goal:** a "Drivers" page that shows what's installed, suggests the PC maker's own tools, and installs signed driver updates from Windows Update one at a time, with a restore point first.

**Owner-approved routes:**
1. Windows Update's driver channel: only drivers Microsoft signs and offers for this PC's hardware.
2. Maker and graphics-vendor tools through the existing catalog.
3. A read-only list of installed drivers.

**Not in scope (v1):**
- Firmware and BIOS installs: shown read-only behind a toggle.
- Driver rollback screen: we point to System Restore and Device Manager.
- Hiding driver updates, because that changes Windows Update's own state.
- Scheduled driver checks and "Update all drivers".
- Driver backup.
- AMD Adrenalin installs (not in winget; we link to amd.com instead).

## Global Constraints
- **How Windows Update is called.** Through the Windows Update Agent COM API via the `windows` crate (0.62, already in Cargo.lock through Tauri):
  - It is in-process: no PowerShell and no child process, because hidden elevated PowerShell is an antivirus trigger.
  - All COM work happens on one dedicated MTA "actor" thread. COM pointers never leave it.
  - Never call `SetServerSelection`, so company update policy is never bypassed.
- **Nothing that decides an install comes from JS or a file.**
  - Only a validated `DriverKey` (update GUID plus revision) and the user's consent ticks cross IPC.
  - The update is re-found in Rust.
  - Firmware, policy and one-at-a-time are checked in the command and again in the worker.
- **Restore point before every driver install** (`SRSetRestorePointW`, `DEVICE_DRIVER_INSTALL`):
  - If System Restore is off, the install doesn't start unless the user ticked "Install without a restore point".
  - Never change Windows' once-a-day restore point limit.
- **Isolation from app updates.** One driver at a time. Drivers never appear in "Update all", the scheduler, backup sources or rules.
- **Plain language** (ADR 027). "Windows Update" may be named; WUA, INF and hardware ids never appear on screen.
- **Pro gate.** `features.rs` holds a single `allowed(Feature::DriverInstall)` check, used by the install command and the worker. The list, search and maker tools stay free.
- **Live checks need owner approval each time:** a real Windows Update scan, and installing one driver.

## Review Focus
1. Metadata from JS or the persisted file deciding what installs. Everything must come from Rust's own `IUpdate`, with firmware and policy checked again in the worker.
2. Restore point mistakes:
   - `CANCELLED_OPERATION` deleting a point after a partial install;
   - the guard not running on panic;
   - the once-a-day limit described as "protected".
3. COM lifetime and threading:
   - an interface escaping the actor thread;
   - a missing `CleanUp`;
   - abort/callback deadlock;
   - a dead actor blocking the queue.
4. Policy bypass, through `SetServerSelection` or by missing the MDM `PolicyManager` key.
5. Regressions from `SourceKind::Driver`:
   - fallback, merge, rules and persist matches;
   - drivers leaking into "Update all";
   - a retry skipping consent.

### D1: Installed drivers list (read-only)
- **Source:** SetupAPI through windows-sys (features `Win32_Devices_DeviceAndDriverInstallation`, `Win32_Devices_Properties`). WMI took 9.2 s on the owner's PC.
  - `SetupDiGetClassDevsW(DIGCF_ALLCLASSES | DIGCF_PRESENT)`.
  - Properties read: FriendlyName, DeviceDesc, Class, DriverVersion, DriverDate, DriverProvider, DriverInfPath, HardwareIds, CompatibleIds, ProblemCode.
  - Signer:
    - a non-`oem*.inf` driver is built into Windows;
    - an `oem*.inf` driver's signer comes from `SetupVerifyInfFileW`, checked once per INF.
- **Types (ts-rs):**
  - `DeviceDriver { deviceName, deviceClass, version, date, provider, signer: Signer{Windows, MicrosoftCertified, Other, Unknown}, builtIn, problem }`
  - `DeviceClass { Display, Network, Audio, Bluetooth, Camera, Input, Storage, System, Firmware, Other }`
- **Behaviour:** cached for 5 minutes and refreshed after a driver job. The default view hides software devices, volumes, print queues, audio endpoints, system devices and WAN miniports; a "Show all devices" toggle reveals them.
- **Command** `list_drivers`. New **Drivers** sidebar page between Installed and Settings.
- **Tests:**
  - classification from a fixture captured on the owner's PC;
  - signer naming;
  - FILETIME to ISO date;
  - hidden classes;
  - hardware-id normalisation;
  - `#[ignore]` live: more than 50 devices in under 2 s.

  - Intel Driver & Support Assistant: `Intel.IntelDriverAndSupportAssistant`
  - NVIDIA App: Store `XP8CLZL93F5Z4P`
  - Dell Command Update: `Dell.CommandUpdate.Universal`
  - Lenovo System Update (ThinkPad): `Lenovo.SystemUpdate`
  - Lenovo Vantage: Store `9WZDNCRFJ4MV`
  - HP Support Assistant: `HP.SupportAssistant`
  - MyASUS: Store `9N7R5S6B0ZZH`
  - AMD graphics: a link card to amd.com/support, because Adrenalin isn't in winget. `AMD.AMDSoftwareCloudEdition` is an Azure VM package and must not be offered.
- **Detection:**
  - maker and model from the registry `HKLM\HARDWARE\DESCRIPTION\System\BIOS`;
  - graphics vendors from the D1 list (display devices' vendor ids).
- **Pure** `drivers/vendor.rs::suggest(maker, model, gpu_vendors)`. Installs go through the existing validated `enqueue`.
- **Tests:**
  - the suggestion table, for example the owner's ASUS laptop with NVIDIA and AMD graphics gives MyASUS, NVIDIA App and the AMD link;
  - the catalog validator passes.

### D3: Check Windows Update for drivers (read-only) and company policy
- **Dependency:** `windows` 0.62 with features `Win32_System_UpdateAgent`, `Win32_System_Com`, `Win32_System_Variant`, `Win32_System_Ole`, `implement`.
- **Actor** `drivers/wua/sys.rs`, the only `unsafe` Windows Update code:
  - `BeginSearch` with criteria `IsInstalled=0 and Type='Driver' and IsHidden=0`;
  - can be cancelled; 10-minute timeout.
- **Mapping** `drivers/wua/map.rs`: `DriverUpdate { key, title, deviceName, deviceClass, manufacturer, provider, version, installedVersion, date, sizeBytes, optional, reboot, hasEula, warning, matchedDevice }`.
  - The device name comes from matching the update's hardware ids against the D1 list; an exact match beats a compatible match.
  - Firmware means the class is Firmware, or the title says firmware, BIOS or UEFI.
  - Network and display updates carry warnings.
- **Policy** `drivers/policy.rs`, pure logic over a registry trait. Any of these marks the PC as managed:
  - `ExcludeWUDriversInQualityUpdate`, under group policy or MDM `PolicyManager`;
  - `DisableWindowsUpdateAccess`;
  - `DoNotConnectToWindowsUpdateInternetLocations`;
  - `SetPolicyDrivenUpdateSourceForDriverUpdates`;
  - `WUServer` / `UseWUServer` set;
  - the update service disabled.

  A managed PC is not searched and can't install, with a plain explanation.
- **Commands:** `check_driver_updates` (manual only) and `get_driver_updates`. `DriverListing` carries the updates, the count of hidden firmware updates, any policy block and the check time.
- **Tests:**
  - mapping fixtures: titles, firmware by class and by title, warnings, multi-device match, fallback name, size;
  - the GUID newtype;
  - every policy combination;
  - `#[ignore]` live scan only with owner approval.

### D4: Restore point and installing one driver
- **New source:** `SourceKind::Driver` with `DriverKey`, validated as a lowercase GUID plus `.revision`. The generic `enqueue`, `update_all` and `retry_job` refuse it.
- **Worker:** `WorkerDeps.drivers: Option<Arc<dyn DriverInstaller>>`, with `execute_driver` running these phases:
  - **Preparing:** policy, consent, re-find, reboot-before-install check.
  - **Waiting:** while Windows Update is busy.
  - **Downloading:** real percent; can be cancelled.
  - **Installing:** restore point, then install, never cancelled.
  - **Verifying:** re-read the D1 row.
- **Restore point guard** (RAII, also runs on panic):
  - `END_SYSTEM_CHANGE` once the install started;
  - `CANCELLED_OPERATION` only if it never started.
- **Commands:**
  - `install_driver(key, consent{acceptEula, riskAcknowledged, noRestorePointOk})`;
  - `driver_eula(key)`, which returns plain text.
- **New failure reasons:** `RestorePointOff`, `UpdateServiceOff`, `UpdatesManaged`.
- **HRESULT map:**
  - 0x8024402C / 0x80072EE7 / 0x80072EFD: Offline
  - 0x80240016: InstallerBusy
  - 0x80070422: UpdateServiceOff
  - 0x8024002E: UpdatesManaged
  - 0x80240017: NoApplicableInstaller
  - anything else: InstallerError
- **Restored jobs:** `persist::recover` names restored driver jobs "Driver update". Consent is used once, so a retried or restored driver job must be started again from Drivers.
- **Tests (fake installer):**
  - phases in order;
  - download percent only goes up;
  - cancel while downloading;
  - Installing can't be cancelled;
  - System Restore off without consent installs nothing;
  - END vs CANCELLED restore point semantics;
  - consent used once;
  - firmware refused even when JS sends its key;
  - managed PC refused;
  - second driver job refused;
  - reboot flag passed through;
  - generic `enqueue` and `update_all` reject drivers.
- **Live:** one owner-approved optional driver that is neither network nor display.

## Honest risks
- **Hybrid graphics:** a display driver from Windows Update can break the maker's hybrid-graphics setup, as on the owner's laptop. The warning suggests the maker's tool instead.
- **Network drivers:** a network driver can cut the internet after install. The download finishes first and the restore point covers it.
- **Windows Update quirks:**
  - first scans can take minutes;
  - "success" may still leave the old driver in use (verification is a note, never a failure);
  - the service may be busy.
- **Unsigned builds:** antivirus may still flag test builds until P7 code signing. In-process COM is low risk.
- **Other management tools:** they may not show up in the registry. Windows Update's own error code is the final word and shows as "managed".
